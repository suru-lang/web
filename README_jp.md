# 屋台(する のウェブフレームワーク)

日本語のプログラミング言語「[する](https://github.com/suru-lang/suru)」のウェブフレームワークです。道(URL)ごとに処理を書き、【道】で道の一覧を1行ずつ書くと、[suru-lang/http](https://github.com/suru-lang/http) の上で動くサーバーになります。中身は全部 する で書いてあり、インタプリタでもコンパイルしたバイナリでも同じに動きます。計画: suru-lang/web#1。

## 入れ方

[kumu](https://github.com/suru-lang/suru/blob/main/README_jp.md#プロジェクトを組むkumu) のプロジェクトで:

```sh
kumu 追加 github.com/suru-lang/web
```

HTTP(suru-lang/http)も依存として一緒に入ります。する 本体は 0.10.0 以上が要ります(【道】が準クォートを、文脈と道筋がフィールドの型を書いた組を使うため)。

## 使い方

```
「屋台」 を 読み込んで 使う
「標準」 を 読み込んで 使う

文脈 を トップ表示する は HTTP内の応答 の 動作
c を トップ表示する とは 「いらっしゃいませ、」 + （c から 「お名前」 を 問い取得して HTML逃避する） + 「さん」 を HTML返答する

文脈 を 品表示する は HTTP内の応答 の 動作
c を 品表示する とは 「品 」 + （c から 「番号」 を 道引数取得する） + 「 です」 を 文字返答する

文脈 を 注文受付する は HTTP内の応答 の 動作
c を 注文受付する とは 「/ありがとう?品=」 + （c から 「品」 を 書式取得する） へ 転送返答する

道群 とは 以下の【道】です
  GET  /           トップ表示する
  GET  /品/:番号    品表示する
  POST /注文        注文受付する
以上です

8080 を （道群 を 記録中継すること で 中継付けする） で 屋台開店する
```

処理は `文脈 を 受け取って HTTP内の応答 の 動作` を返す関数です。`8080 を 道群 で 屋台開店する` で 8080 番で待ち受け、要求ごとに合う道の処理を呼びます。例は [例/店.suru](例/店.suru) です(`例/` のフォルダで `kumu 実行` し、http://localhost:8080/ を開きます)。

## 道を書く(【道】)

`道群 とは 以下の【道】です` の下に、字下げして1行に1つずつ `方法 道の型 処理` を書き、`以上です` で閉じます。

- 方法は `GET`・`POST`・`PUT`・`PATCH`・`DELETE` です。
- 道の型は `/` で始めます。`:名前` の部品はどんな部品にも合い、`c から 「名前」 を 道引数取得する` で取れます。最後の `*` は残りの部品の全部に合います(引数の名前は `*`)。
- 処理は `品表示する` か `品表示すること` の形の名前です。
- 空の行と、`#` から後は読みません。間違った行は、その行を指して知らせます(`【道】の2行目: 道の型『品』は / で始めます`)。

1行は `（「GET」 と 「/品/:番号」 と 品表示すること の 道筋）` と同じで、【道】を使わずにこう書いてもかまいません。

## 決めたこと

1. **処理は関数、道は組。** 処理は `文脈` を受け取って `HTTP内の応答` の動作を返す関数です。`道筋` は方法(`道方法`)・道の型(`道型`)・処理(`道処理`)の組で、フィールドの型を書いて定義しています。設定ファイルや注釈の印は使いません。
2. **振り分けは書いた順。** `道群 で 要求 を 振分する` は、道の型と方法が合う最初の道の処理を呼びます。道の型に合う道があって方法だけが違えば 405(`Allow` に使える方法)、どれにも合わなければ 404 です。HEAD の要求には GET の道が合います(HTTP が見出しだけを送ります)。
3. **道は %XX を戻してから比べる。** 道の `?` と `#` の後ろを除き、`/` で分けた部品ごとに %XX を戻してから道の型と比べます。戻せない道は 400 です。`道引数取得する` の値も戻した後の文字列です。
4. **問いと書式は名前で取る。** `問い取得する` は道の `?` の後ろ、`書式取得する` は本文(`application/x-www-form-urlencoded`)から、名前の値を取ります。`+` は空白にし、%XX を戻します(戻せなければそのまま)。同じ名前が2つあれば前のもの、なければ `「」` です。
5. **応答を作る関数は動作を返す。** `文字返答する`・`HTML返答する`・`JSON返答する`(「JSON」の値)・`状態返答する`・`転送返答する`・`静的返答する` は `HTTP内の応答` の動作を返すので、処理の本体にそのまま書けます。`転送返答する` は 303 See Other で、書式を受けた後に使います。行き先の ASCII でない字は %XX にします。
6. **中継は処理を包む関数。** 中継は処理を受け取って処理を返す関数です。`道群 を 中継 で 中継付けする` で、どの道の処理も包みます。`記録中継する` は、答えるたびに `GET /品/1 200` を表示します。
7. **静的ファイルは HTTP の配信に任せる。** `「公開」 から 「/静的」 を c で 静的返答する` は、道の `/静的` より後ろを 公開 の下のファイルとして `HTTP内の配信する` で返します。`GET /静的/* 静的配信する` のような道から使います。フォルダの外を指す道は HTTP が 403 にします。
8. **画面に出す値は逃がす。** `HTML逃避する` は `&`・`<`・`>`・`"`・`'` を文字参照にします。問いや書式の値を HTML に入れるときに使います。
9. **【道】は `屋台` の `道展開する`。** 準クォートの展開の関数(`文字列 を 道展開する は 文字列 の 成否`)で、`道筋` のリストの式を作ります。作ったコードは `道筋` を前置きなしで使うので、`「屋台」 を 読み込んで 使う` と書きます。

## 試験

```sh
kumu 試験     # 振り分け・文脈・応答・中継・【道】(サーバーは立てません)
kumu 点検
```

CI では、ほかに `例/` の店を作って起動し、curl で答えを確かめます。

## 今後の候補

計画(suru-lang/web#1)の後の段階です。

- クッキーとセッション、CSRF の守り

- `kumu 新規 --対象 web` の雛形のプロジェクト

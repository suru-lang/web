# 屋台(する のウェブフレームワーク)

日本語のプログラミング言語「[する](https://github.com/suru-lang/suru)」のウェブフレームワークです。道(URL)ごとに処理を書き、【道】で道の一覧を1行ずつ書くと、[suru-lang/http](https://github.com/suru-lang/http) の上で動くサーバーになります。中身は全部 する で書いてあり、インタプリタでもコンパイルしたバイナリでも同じに動きます。計画: suru-lang/web#1。

## 入れ方

[kumu](https://github.com/suru-lang/suru/blob/main/README_jp.md#プロジェクトを組むkumu) のプロジェクトで:

```sh
kumu 追加 github.com/suru-lang/web
```

HTTP(suru-lang/http)・雛形(suru-lang/template)・台帳(suru-lang/orm)も依存として一緒に入ります。する 本体は 0.11.0 以上が要ります(【道】が準クォートを、文脈と道筋がフィールドの型を書いた組を使い、セッションの署名に「ハッシュ」の HMAC-SHA256 を使うため)。

## プロジェクトを始める

`kumu 新規 店 --対象 web`(する 0.11.0 以上)で、必要なものがそろったウェブアプリを作れます。

```
店/
  組.suru          github.com/suru-lang/web に依存
  本体.suru        8080 番でサーバーを開く
  店.suru          道(【道】)と処理
  画面/            テンプレート: 配置.html(枠)と トップ.html
  公開/            静的ファイル(見た目.css)
  試験/道.suru     サーバーを立てずに道を確かめる試験
```

- **開発する。** `kumu 実行` で作って動かし、http://localhost:8080/ を開きます。頁は要求ごとに `画面/` から読むので、テンプレートを直せば起動し直さずに変わります。コンパイルを待たずに動かすなら、`kumu 取得` を一度してから `suru 本体.suru` とインタプリタで動かします。
- **試験する。** `kumu 試験` で `試験/道.suru` を動かします。要求を `振分する` で `道群` に直接送ります。`kumu 点検` でプロジェクトを点検します。
- **出す。** `kumu 作る` でバイナリ `出力/店` を作ります。動かしたフォルダの `画面/` と `公開/` を読むので、そのフォルダを隣に置き、そこで起動します。

## 使い方

```
「屋台」 を 読み込んで 使う
「標準」 を 読み込んで 使う

文脈 を トップ表示する は HTTP内の応答 の 動作
c を トップ表示する とは 「いらっしゃいませ、」 + （c から 「お名前」 を 問い取得して HTML逃避する） + 「さん」 を HTML返答する

文脈 を 品表示する は HTTP内の応答 の 動作
c を 品表示する とは 「品 」 + （c から 「番号」 を 道引数取得する） + 「 です」 を 文字返答する

文脈 を 注文受付する は HTTP内の応答 の 動作
c を 注文受付する とは 「/ありがとう?品=」 + （c から 「品」 を 書式取得する） へ 転送返答する

道群 とは 以下の【道】です
  GET  /           トップ表示する
  GET  /品/:番号    品表示する
  POST /注文        注文受付する
以上です

8080 を （道群 を 記録中継すること で 中継付けする） で 屋台開店する
```

処理は `文脈 を 受け取って HTTP内の応答 の 動作` を返す関数です。`8080 を 道群 で 屋台開店する` で 8080 番で待ち受け、要求ごとに合う道の処理を呼びます。例は [例/店.suru](例/店.suru) です(`例/` のフォルダで `kumu 実行` し、http://localhost:8080/ を開きます)。

## 道を書く(【道】)

`道群 とは 以下の【道】です` の下に、字下げして1行に1つずつ `方法 道の型 処理` を書き、`以上です` で閉じます。

- 方法は `GET`・`POST`・`PUT`・`PATCH`・`DELETE` です。
- 道の型は `/` で始めます。`:名前` の部品はどんな部品にも合い、`c から 「名前」 を 道引数取得する` で取れます。最後の `*` は残りの部品の全部に合います(引数の名前は `*`)。
- 処理は `品表示する` か `品表示すること` の形の名前です。
- 空の行と、`#` から後は読みません。間違った行は、その行を指して知らせます(`【道】の2行目: 道の型『品』は / で始めます`)。

1行は `（「GET」 と 「/品/:番号」 と 品表示すること の 道筋）` と同じで、【道】を使わずにこう書いてもかまいません。

## 画面(雛形)

頁は、フォルダ(ここでは `画面/`)の [雛形](https://github.com/suru-lang/template) のテンプレートで書きます。

```
「屋台」 を 読み込んで 使う
「JSON」 を 読み込んで 使う

画面 とは （「画面」 を 画面設定する） に 「配置.html」 を 配置設定する

品頁 とは 題 は 文字列 で 値段 は 数 の 組
品頁 は 【JSON】 を 導出する

文脈 を 品表示する は HTTP内の応答 の 動作
c を 品表示する とは 「品.html」 を 頁 で 画面 に 画面返答する
ただし 頁 とは （題 は （c から 「名前」 を 道引数取得する） で 値段 は 120 の 品頁） を 品頁JSON化する
```

```
{# 画面/配置.html #}
<!doctype html>
<title>{{ 題 }} - 屋台</title>
<main>{{ 中身 を 生にする }}</main>

{# 画面/品.html #}
<h1>{{ 題 }}</h1>
<p>{{ 値段 }}円</p>
```

- `「画面」 を 画面設定する` は、フォルダ 画面 のテンプレートを使います。自分のフィルターや部品を足した雛形の設定からは、`設定 を 雛形画面設定する` で作ります。
- `画面 に 「配置.html」 を 配置設定する` は、どの頁も枠 配置.html に入れます。枠には頁の値と `中身`(描いた頁)が渡り、`{{ 中身 を 生にする }}` で書きます。
- `「品.html」 を 値 で 画面 に 画面返答する` は、`値`(「JSON」の物)を差し込んだ頁の応答の動作です。描けなければ、理由を付けて 500 で答えます。`画面描画する` は、描いた文字列を `成否` で返します。
- 値は、【JSON】で導出した組(`品頁JSON化する`)で書くと楽です。

## JSON の本文と書式

本文の JSON は、【JSON】で導出した型にそのまま戻せます。

```
注文 とは 品 は 文字列 で 数 は 数 の 組
注文 は 【JSON】 を 導出する

文脈 を 注文受付する は HTTP内の応答 の 動作
c を 注文受付する とは （c を 注文JSON復元すること で JSON本文復元する） を 注文返答すること で 成功時返答する

注文 を 注文返答する は HTTP内の応答 の 動作
o を 注文返答する とは （o を 注文JSON化する） を JSON返答する
```

- `c を JSON本文解析する` は本文の JSON を `成否` で返します。`c を 会員JSON復元すること で JSON本文復元する` は、導出した型に戻します。
- `r を 処理 で 成功時返答する` は、`成功` なら中身を処理に渡し、`失敗` なら理由(たとえば `数が数ではありません`)を付けて 400 で答えます。

書式の値は、規則(`書式規則`)で確かめます。

```
規則群 とは （「品」 を 必須検査する） と （「数」 を 1 から 9 へ 範囲検査する） と （「備考」 を 200 で 最長検査する）

文脈 を 書式受付する は HTTP内の応答 の 動作
c を 書式受付する とは
  もし 誤り群 = 空 ならば 「/ありがとう」 へ 転送返答する
  そうでなければ 422 と 「品.html」 を （誤り群 を 誤りJSONにする） で 画面 に 画面状態返答する
ただし 誤り群 とは c を 規則群 で 書式検査する
```

- 規則は `必須検査する`(空でない)・`数検査する`(数)・`範囲検査する`(… から … までの数)・`最長検査する`(n 字まで)・`選択検査する`(候補のどれか)です。
- `c を 規則群 で 書式検査する` は `書式誤り`(欄 `誤欄` と文 `誤文`)のリストを返します。空なら誤りはありません。
- `誤り群 を 誤りJSONにする` は、欄ごとに最初の文を書いた JSON の物で、画面に渡せます(`{% もし 数 ならば %}{{ 数 }}{% 以上 %}`)。`画面状態返答する` は、422 などの状態で頁を答えます。

## クッキー・セッション・CSRF

```
秘密 とは 「長くて秘密の文字列です。リポジトリには入れません」 を セッション設定する

文脈 を 回数表示する は HTTP内の応答 の 動作
c を 回数表示する とは （「回数: 」 + （n を 文字列化する） を 文字返答する） に 新値 を 秘密 で セッション保存する
ただし n とは （（c を 秘密 で セッション取得する） から 「回数」 を JSON取得する） を 回数にする
ただし 新値 とは （（「回数」 と （n + 1 の JSON数） の JSON項目） を 空 に 挿入する） の JSON物

JSON を 回数にする は 数
（n の JSON数） を 回数にする とは n
v を 回数にする とは 0

8080 を （道群 を （秘密 で CSRF中継すること） で 中継付けする） で 屋台開店する
```

- `c から 「名」 を クッキー取得する` でクッキーを読みます。`応答の動作 に 「名」 と 値 を クッキー付けする` は `Set-Cookie`(`Path=/; HttpOnly; SameSite=Lax`)を足し、`クッキー属性付けする` は属性を自分で書き、`クッキー消去する` は消します。
- `「…」 を セッション設定する` でセッションの設定を作ります。`c を 秘密 で セッション取得する` はセッション(JSON の物。ない・署名が合わなければ空の物)、`応答の動作 に 値 を 秘密 で セッション保存する` は値に署名してクッキーにします。
- `（秘密 で CSRF中継すること）` は中継です。GET ではクッキー 屋台札 に札を入れ、`c を CSRF札取得する` で書式に `<input type="hidden" name="_札" value="{{ 札 }}">` として入れます。POST・PUT・PATCH・DELETE は、`_札`(か見出し `X-CSRF-Token`)がクッキーと合わなければ 403 です。

## 資源の道(台帳)

【表】と【JSON】を導出した組は、【道】の1行で JSON の API になります。台帳は [suru-lang/orm](https://github.com/suru-lang/orm) です。DB の駆動(ここでは SQLite)は自分のプロジェクトに足します。

```
「屋台」 を 読み込んで 使う
「JSON」 を 読み込んで 使う
「蔵」 を 読み込んで 使う
「台帳」 を 読み込んで 使う
「SQLite」 を 読み込んで 使う

会員 とは 番号 は 数 で 名前 は 文字列 で 年齢 は 数 の 組

会員 は 【表】 と 【JSON】 を 導出する

帳場接続する は DB接続 の 動作
帳場接続する とは 「店.db」 を SQLite駆動 で DB開封する

道群 とは 以下の【道】です
  資源 /会員  会員 帳場接続する
以上です
```

- `資源 道 組の名前 接続の名前` で6つの道になります。
  - `GET /会員` は一覧を JSON の配列で返します。`?開始=20&上限=10` で一部だけを返します。
  - `POST /会員` は JSON の本文から作り、組と `Location: /会員/番号` を付けて 201 で答えます。
  - `GET /会員/:番号` は1つを返します。
  - `PUT /会員/:番号` と `PATCH /会員/:番号` は JSON の本文で直します。
  - `DELETE /会員/:番号` は消して 204 で答えます。
- ない番号や、1 以上の整数でない番号は 404、読めない本文や型に合わない本文は 400 です。
- 【道】を使わないときは `「/会員」 を （資表 は 会員表 で 資化 は 会員JSON化すること で 資戻 は 会員JSON復元すること で 資開 は （帳場接続する） の 資源） で 資源道群にする` と書きます。`道筋` のリストになるので、ほかの道と `+` でつなげます。

## 決めたこと

1. **処理は関数、道は組。** 処理は `文脈` を受け取って `HTTP内の応答` の動作を返す関数です。`道筋` は方法(`道方法`)・道の型(`道型`)・処理(`道処理`)の組で、フィールドの型を書いて定義しています。設定ファイルや注釈の印は使いません。
2. **振り分けは書いた順。** `道群 で 要求 を 振分する` は、道の型と方法が合う最初の道の処理を呼びます。道の型に合う道があって方法だけが違えば 405(`Allow` に使える方法)、どれにも合わなければ 404 です。HEAD の要求には GET の道が合います(HTTP が見出しだけを送ります)。
3. **道は %XX を戻してから比べる。** 道の `?` と `#` の後ろを除き、`/` で分けた部品ごとに %XX を戻してから道の型と比べます。戻せない道は 400 です。`道引数取得する` の値も戻した後の文字列です。
4. **問いと書式は名前で取る。** `問い取得する` は道の `?` の後ろ、`書式取得する` は本文(`application/x-www-form-urlencoded`)から、名前の値を取ります。`+` は空白にし、%XX を戻します(戻せなければそのまま)。同じ名前が2つあれば前のもの、なければ `「」` です。
5. **応答を作る関数は動作を返す。** `文字返答する`・`HTML返答する`・`JSON返答する`(「JSON」の値)・`状態返答する`・`転送返答する`・`静的返答する` は `HTTP内の応答` の動作を返すので、処理の本体にそのまま書けます。`転送返答する` は 303 See Other で、書式を受けた後に使います。行き先の ASCII でない字は %XX にします。
6. **中継は処理を包む関数。** 中継は処理を受け取って処理を返す関数です。`道群 を 中継 で 中継付けする` で、どの道の処理も包みます。`記録中継する` は、答えるたびに `GET /品/1 200` を表示します。
7. **静的ファイルは HTTP の配信に任せる。** `「公開」 から 「/静的」 を c で 静的返答する` は、道の `/静的` より後ろを 公開 の下のファイルとして `HTTP内の配信する` で返します。`GET /静的/* 静的配信する` のような道から使います。フォルダの外を指す道は HTTP が 403 にします。
8. **画面に出す値は逃がす。** `HTML逃避する` は `&`・`<`・`>`・`"`・`'` を文字参照にします。問いや書式の値を HTML に入れるときに使います。
9. **【道】は `屋台` の `道展開する`。** 準クォートの展開の関数(`文字列 を 道展開する は 文字列 の 成否`)で、`道筋` のリストの式を作ります。作ったコードは `道筋` を前置きなしで使うので、`「屋台」 を 読み込んで 使う` と書きます。
10. **画面はファイルから読む雛形のテンプレート。** `画面返答する` は要求ごとにテンプレートのファイルを読むので、頁を直せば起動し直さずに変わります。`.html` のテンプレートでは、`{{ }}` を HTML の逃がしにします(雛形の自動の逃がし)。
11. **配置は2つ目のテンプレート。** 先に頁を描き、それから頁の値と `中身` で枠を描きます。枠は `{{ 中身 を 生にする }}` と書き、頁を2回逃がさないようにします。頁の中では雛形の継承(`継承する`)も使えます。
12. **読めない JSON の本文は送った側の誤り。** `成功時返答する` は、読めない本文や型に合わない本文に、【JSON】の戻す関数の理由を付けて 400 で答えます。Content-Type は見ません。
13. **書式の規則は値。** 規則は `書式規則` の組(欄の名前・必須か・値から文への関数。よければ `「」`)です。`必須検査する` のほかの規則は空の値を確かめないので、なくてもよい欄にも規則を付けられます。文は日本語で、欄の名前を入れます。
14. **セッションは署名したクッキー。** サーバーには何も残しません。セッションは JSON の物の Base64、`.`、その HMAC-SHA256 の16進を、クッキー 屋台 に入れたものです。中身は誰でも読めますが、変えると署名が合わなくなります。秘密は入れません。クッキーは 4KB ほどまでです。鍵を変えると、全員のセッションが消えます。
15. **CSRF は署名した札を2か所に送らせる。** 札は OS の乱数の16バイトとその署名です。クッキー(HttpOnly ではない)に入れ、書式か見出し `X-CSRF-Token` で同じものを送り返させます。GET・HEAD・OPTIONS は確かめないので、それらの処理では何も変えません。JSON の API のようにクッキーを使わない道は、中継から外してかまいません。
16. **署名は同じ時間で比べる。** 全部のバイトを比べてから答えるので、偽の署名のどこが違ったかが時間からわかりません。
17. **資源は要求ごとに接続を開く。** `資開` は `DB接続` を開く動作です。要求ごとに開いて使い、閉じるので、動かしたまま DB を変えてもよく、別のスレッドの要求が接続を分け合いません。
18. **主鍵は最初の列で、道から取る。** 作るときは本文の主鍵を使わず、DB が決めます。直すときは道の番号を使います。PUT も PATCH も全部の列を置き換えるので、本文には主鍵のほかの欄を全部書きます。
19. **資源の道は自分では CSRF を確かめない。** JSON の API なので、`CSRF中継する` から外すか、札を `X-CSRF-Token` で送ります。

## 試験

```sh
kumu 試験     # 振り分け・文脈・応答・中継・【道】・画面・JSON の本文・書式・クッキー・セッション・CSRF(サーバーは立てません)
kumu 点検
cd 結合試験 && kumu 試験   # 資源の道を本物の SQLite で(SQLite が要ります)
```

CI では、ほかに `例/` の店を作って起動し、curl で答えを確かめます。
